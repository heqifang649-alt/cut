# GC Cutflow 交接与账号切换

## 当前部署

- 网站与 Worker：D:\自动剪辑网站
- 网站地址：http://192.168.30.38:3001/
- Codex 执行账号目录：D:\codex\.codex
- Codex 缓存：D:\codex\cache
- Codex 临时文件：D:\codex\tmp
- 审核通过后的成片：E:\尔尔本地\素材\基督\自动剪辑\成片
- E 盘旧网站项目暂时保留，只用于回退，不再作为生产入口。

## 账号隔离原则

网页不直接登录 Codex，也不保存账号密码。网页只把素材路径、统一需求、样片规则、产品分组、EDL、修改指令和任务状态写入本地任务包。

Worker 固定通过 CODEX_HOME=D:\codex\.codex 调用当前执行账号。旧 threadId 不是任务事实来源；切换账号后，每个阶段创建新线程，并从 reference-profile.json、product-groups.json、batch-edl.json 和批次指令恢复上下文。

因此：

1. 切换 Codex 桌面端账号不会自动切换网站 Worker。
2. 必须使用本项目提供的账号切换脚本更新 Worker 凭证。
3. 网站重启前会真实运行一次 READY 连通测试；测试失败时拒绝启动 Worker。

## 切换 Codex 账号

1. 等待当前任务完成，或先在网页点击“取消任务”。
2. 在 PowerShell 运行：

   powershell -ExecutionPolicy Bypass -File D:\自动剪辑网站\scripts\switch-codex-account.ps1

3. 按终端提示在浏览器完成新账号登录。
4. 登录脚本会备份旧凭证、验证新账号并写入账号状态。
5. 运行：

   powershell -ExecutionPolicy Bypass -File D:\自动剪辑网站\scripts\restart-cutflow.ps1

6. 打开 http://192.168.30.38:3001/，确认“剪辑工作机已连接”。

旧凭证备份保存在 D:\codex\account-backups。不得把 auth.json 上传、发群或写入网页任务数据。

## 日常启动

运行：

powershell -ExecutionPolicy Bypass -File D:\自动剪辑网站\scripts\start-cutflow.ps1

启动脚本会：

1. 固定使用 D 盘 Codex 账号、缓存和临时目录。
2. 执行账号连通测试。
3. 启动网站、主剪辑 Worker、样片 Worker 和交付 Worker。
4. 检查网站健康状态。

## ChatCut 单向同步

自动系统仍是批量任务的唯一事实来源。每条视频保存 MP4、剪辑清单和 ChatCut 项目标识；只把实际使用的原始片段及时间线同步到 ChatCut。ChatCut 中的人工特例不自动写回批量规则。

ChatCut 登录凭证与 Codex 凭证分开管理。切换其中一个账号不会自动覆盖另一个账号。

## 验收清单

- D:\自动剪辑网站\data\batches.json 和 storage 目录存在。
- http://localhost:3001/api/health 返回 workerOnline=true。
- data\codex-account-state.json 中 ready=true。
- 新任务能够从 queued 进入分析或剪辑状态。
- 切换账号后旧 threadId 不会导致任务失败。
- NAS 原片保持只读。
- 所有模型动作保持 1.00 倍速。
- 同一批次不同成片使用不同音乐。
- 质检通过前成片不会进入正式交付目录。

## 回退

如果 D 盘部署无法启动，不删除任何 D 盘或 E 盘数据。先停止 D 盘进程，再使用旧 E 盘启动脚本恢复服务。回退期间不要同时启动两套 Worker，避免两个进程同时消费同一个业务批次。

## 不能绝对保证的外部因素

无法对网络中断、OpenAI/ChatCut 服务不可用、账号额度耗尽、NAS 断线或磁盘损坏作 100% 保证。系统通过启动门禁、任务文件化、凭证备份、原子 JSON 写入和旧项目保留，把这些问题变成明确报错并支持恢复，不允许静默切到错误账号继续处理。
